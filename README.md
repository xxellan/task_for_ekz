# Система интернет-магазина на C++

## 3.1 Описание задачи

**Цель работы:**  
Разработать систему интернет-магазина с использованием принципов объектно-ориентированного программирования, умных указателей и работы с PostgreSQL. Система должна поддерживать работу пользователей разных ролей, управление заказами, оплату, историю изменений и аудит.

**Описание реализованной системы:**  
- Пользователи: **Администратор**, **Менеджер**, **Покупатель**.  
- Товары добавляются, обновляются и удаляются администратором.  
- Покупатели могут создавать заказы, добавлять товары, оплачивать и оформлять возврат.  
- Менеджеры утверждают заказы и обновляют наличие товара на складе.  
- Вся система использует транзакции и ведет историю изменений заказов и операций (audit log).  

**Используемые технологии:**  
- C++17  
- PostgreSQL  
- Библиотека `libpqxx` для работы с базой данных PostgreSQL  
- STL, умные указатели (`std::unique_ptr`, `std::shared_ptr`)  


## 3.2 Архитектура проекта

**Основные классы:**

| Класс | Назначение |
|-------|------------|
| `DatabaseConnection<T>` | Шаблонный класс для подключения к PostgreSQL и выполнения запросов |
| `User` (базовый) | Базовый класс для пользователей с методами создания заказа и просмотра статуса |
| `Admin`, `Manager`, `Customer` | Наследники User с расширенными методами управления товарами, заказами и оплатой |
| `Order` | Управление заказом, хранение OrderItem и объекта Payment |
| `OrderItem` | Элементы заказа (композиция внутри Order) |
| `Product` | Информация о товаре |
| `Payment`, `PaymentStrategy` | Абстрактная стратегия оплаты с конкретными реализациями (карта, электронный кошелёк, СБП) |

**Принципы ООП:**
- **Наследование:** Admin, Manager, Customer наследуются от User.  
- **Полиморфизм:** Чисто виртуальные функции в User и PaymentStrategy.  
- **Композиция:** Order владеет OrderItem и Payment (через `std::unique_ptr`).  
- **Агрегация:** User хранит заказы через `std::shared_ptr<Order>`.

**Использование `DatabaseConnection<T>`:**  
- Позволяет подключаться к базе, выполнять запросы (`executeQuery`, `executeNonQuery`), управлять транзакциями и триггерами.


## 3.3 Работа с базой данных

**Структура базы данных:**  

**Таблицы:**
1. `users` – информация о пользователях (id, имя, email, роль, уровень лояльности).  
2. `products` – информация о товарах (id, название, цена, количество на складе).  
3. `orders` – заказы пользователей (id, статус, итоговая сумма, дата).  
4. `order_items` – элементы заказа (id, заказ, товар, количество, цена).  
5. `order_status_history` – история изменений статусов заказов.  
6. `audit_log` – журнал операций пользователей (добавление, обновление, удаление, оплата).  

**Хранимые процедуры и функции:**
- `createOrder` – создание заказа с проверкой наличия товара и расчётом итоговой суммы.  
- `getOrderStatus(order_id)` – получение текущего статуса заказа.  
- `getUserOrderCount(user_id)` – количество заказов пользователя.  
- `getTotalSpentByUser(user_id)` – общая сумма потраченных денег пользователем.  
- `canReturnOrder(order_id)` – проверка возможности возврата заказа (не более 30 дней).  
- `getOrderStatusHistory(order_id)` – получение полной истории изменения статусов заказа.  

**Триггеры:**
- Автоматическое обновление даты заказа при смене статуса.  
- Обновление `total_price` при изменении цены товара.  
- Автоматическая запись в `order_status_history` и `audit_log`.

**Транзакции и откат:**  
Все критические операции (создание заказа, оплата, изменения продуктов) выполняются в транзакциях. В случае ошибки происходит откат и запись события в `audit_log`.


## 3.4 Умные указатели и STL

**Использование умных указателей:**
- `std::unique_ptr<Payment>` – исключительное владение объектом оплаты заказа.  
- `std::shared_ptr<Order>` – совместное владение заказами между пользователем и системой.  
- `make_unique` и `make_shared` – безопасное создание объектов без использования `new/delete`.  

**Примеры использования STL и лямбда-выражений:**
- `std::find_if` – поиск первого завершённого заказа:

```cpp
auto completedIt = find_if(allOrders.begin(), allOrders.end(),
    [](const shared_ptr<Order>& order) {
        return order->getStatus() == "completed";
    });
std::copy_if – копирование всех завершённых заказов:

vector<shared_ptr<Order>> completedOrders;
copy_if(allOrders.begin(), allOrders.end(), back_inserter(completedOrders),
    [](const shared_ptr<Order>& order) { return order->getStatus() == "completed"; });


std::accumulate – подсчёт общей суммы заказов:

double totalAmount = accumulate(allOrders.begin(), allOrders.end(), 0.0,
    [](double sum, const shared_ptr<Order>& order) { return sum + order->getOrderTotal(); });

3.5 Логика ролей и прав доступа
Роль	        Возможности	                                                                                          Ограничения
Администратор   Добавление/обновление/удаление товаров,просмотр всех заказов,изменение статусов,формирование отчётов  Нет ограничений
Менеджер	    Утверждение заказов,обновление количества на складе,просмотр заказов                                  Доступ только к заказам и аудиту, с которыми работал
Покупатель	    Создание заказов,добавление/удаление товаров,оплата, возврат,просмотр своих заказов	                  Нет доступа к истории изменений других пользователей

Проверка прав доступа реализована через лямбда-функции при выполнении операций.

3.6 Аудит и история изменений

Таблицы:

order_status_history – хранит изменения статусов заказов (id заказа, старый и новый статус, время, кто изменил).

audit_log – журнал операций (добавление, изменение, удаление, оплата).

Примеры записей аудита:
log_id	entity_type	 entity_id	operation	performed_by	performed_at
1	    product	     1	        insert	    1	            2026-01-13 20:00
6	    order	     101	    insert	    3	            2026-01-13 20:10
8	    order	     101	    payment	    3	            2026-01-13 20:20

3.7 Отчёт в формате CSV
Отчёт «История изменений заказов и действий пользователей»:
Файл: reports/audit_report.csv

Пример содержимого CSV:
log_id,entity_type,entity_id,operation,performed_by,performed_at
1,product,1,insert,1,2026-01-13 20:00
6,order,101,insert,3,2026-01-13 20:10
8,order,101,payment,3,2026-01-13 20:20

SQL-запрос для формирования отчёта:

COPY (
    SELECT log_id, entity_type, entity_id, operation, performed_by, performed_at
    FROM audit_log
    ORDER BY performed_at
) TO '/path/to/reports/audit_report.csv' WITH CSV HEADER;
